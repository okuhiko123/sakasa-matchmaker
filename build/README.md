# データの更新手順

掲載者が増えたり、募集状況が変わったら、この2つを順に走らせれば `data.js` と `img/` が作り直される。
アプリ側（`index.html` / `app.css` / `app.js`）は触らなくてよい。

```bash
cd /Users/okudakeita/Developer/sakasama-uranai
./build/fetch.sh          # さかさま不動産から取得（数分かかる）
python3 build/build.py    # data.js と img/*.webp を作り直す
```

Pillow が要る。入っていなければ `pip3 install Pillow`。

## 何をしているか

**fetch.sh**

1. `https://sakasama-fudosan.com/lessee/` を1枚取る。ここに全掲載者のカードが載っている（ページ送りなし）。
2. カードから slug・氏名・肩書・募集状況を読み、**募集中の人だけ**を対象にする。
   「物件が見つかりました」「募集を終了しました」などの表記ゆれは、`_matchingOther` が付いているかどうかで判定している（付いていない＝募集中）。
3. 各人の個別ページ `/lessee/<slug>/` と、カードの写真を取る。

**build.py**

1. 個別ページの HTML から「やりたいこと」「やりたい理由」「希望物件の基本情報」「物件を探している地域」を抜く。
   WP REST API (`/wp-json/wp/v2/lessee`) は `content` も `acf` も空なので、**HTML を読むしかない**。
2. 「希望物件の基本情報」は書式がばらばら（`希望賃貸価格` / `理想賃貸金額` / `賃料` …）なので、キーを緩く寄せて読む。
   金額は「15万円以下」「〜6万円」「10万円前後」などを円に、広さは「80平米以上」「101〜300㎡」「10畳以上」「4LDK」を㎡に直す。
3. やりたいことの本文からキーワードで用途タグ（カフェ／子ども／福祉／工房…）と、改装したい・人が集まる・静かに使う、といった性格を立てる。
4. 市区町村は `build/muni.json`（総務省の全国地方公共団体コード、令和6年1月1日現在）と突き合わせる。**その人の希望都道府県に実在する名前だけ**を採るので、「三重県の人に愛知の市が混ざる」ことがない。コード表を新しくするときは https://www.soumu.go.jp/denshijiti/code.html から xlsx を落として `muni.json` を作り直す。
5. 写真は 512×384 のタイルにして、6×6 の **スプライトシート** `img/sheet-*.webp` にまとめる（463枚で13枚・約10MB）。個別ファイルにすると Artifact の255ファイル上限に当たるため。
6. `muni.js`（都道府県 → その県の全市区町村）も書き出す。市町村の選択肢はこれを使うので、掲載者が市町村を書いていない県でも選べる。

## 既知のクセ

- パスワード保護された記事（タイトルが「保護中:」）は落とす。
- 賃料欄に購入額を書いている人がいる（「1000万円くらい」）。100万円を超える賃料は「相談」扱いにしている。
- 「全国」と書いている人は、どの都道府県を選んでも候補に出るが、県を名指ししている人より低く評価する。
- 掲載者が0人の県では、隣接県（`app.js` の `NEIGHBOR`）まで広げて占う。
- 掲載者が市区町村を書いていない県では、市町村の絞り込み画面そのものを飛ばす。
